# Fault Analysis — NUCLEO-F446RE (Cortex-M4)

크래시가 났을 때 **원인 지점을 소스에서 특정하는 경로**를 확보하기 위한 실험 기록임.

부팅 시퀀스 추적과 시간 측정에 앞서, 문제가 생겼을 때 쓸 도구를 먼저 갖추는 것이 목적이었음.

- 대상: Zephyr v4.4.99, NUCLEO-F446RE (STM32F446RE, Cortex-M4)
- 도구: UART 콘솔, `addr2line`
- 관련 커밋: `app: add fault experiment`, `app: record measured results`

---

## 1. 실험 설계

CPU가 메모리에 접근하는 방식은 세 가지이고, 각각 하드웨어 경로와 오류 처리 방식이 다름.

| | 동작 |
|---|---|
| **Store (쓰기)** | 데이터를 메모리에 씀 |
| **Load (읽기)** | 메모리에서 데이터를 가져옴 |
| **Fetch (인출)** | 실행할 **명령어**를 가져옴 |

"잘못된 주소에 접근하면 크래시가 난다"가 셋 모두에서 참인지 확인하기 위해,
매핑되지 않은 주소(`0xDEADC0DE`)에 세 방식으로 접근해 봄.

```c
/* [1] 쓰기 */
*(volatile unsigned int *)0xDEADC0DE = 42;

/* [2] 읽기 */
volatile unsigned int v = *(volatile unsigned int *)0xDEADC0DE;

/* [3] 점프 (명령어 인출) */
((void (*)(void))0xDEADC0DE)();
```

`volatile`이 없으면 컴파일러가 "결과를 아무도 안 쓰는 접근"으로 판단해 코드를 제거함.
그러면 실험 자체가 성립하지 않으므로 필수임.

---

## 2. 결과 — 예상과 달랐음

| 접근 | 결과 | 원인 |
|---|---|---|
| **쓰기** | **통과** | Cortex-M은 store를 **쓰기 버퍼**에 넣고 결과를 기다리지 않음 |
| **읽기** | **통과, `value=0`** | 이 영역(FMC 미활성)이 버스 에러 대신 **0을 반환** |
| **점프** | **MPU FAULT** | 명령어 인출은 MPU가 차단 |

실험 전 가설은 **"읽기는 CPU가 값을 기다리므로 즉시 fault"** 였으나 틀렸음.

### 이것이 MCU 디버깅의 함정

잘못된 포인터로 읽었는데 **크래시도 나지 않고 그럴듯한 값(0)이 반환됨.**
문제는 수백 줄 뒤에 이상 동작으로 나타나고, 그때는 원인 지점이 이미 지나가 있음.

호스트 환경에서 잘못된 접근이 즉시 신호로 잡히는 것과 다름.
**"에러가 안 났다"가 "정상"을 뜻하지 않는다**는 것을 실측으로 확인함.

## 3. 크래시 덤프 판독

```
***** MPU FAULT *****
  Instruction Access Violation
r0/a1:  0x00000017  r1/a2:  0x08005746  r2/a3:  0x00000000
r3/a4:  0x080025a1 r12/ip:  0x200011b4 r14/lr:  0x0800123f
 xpsr:  0x60000000
r4/v1:  0xdeadc0de  r5/v2:  0x08005454  r6/v3:  0x08005454
EXC_RETURN: 0xfffffffd
Faulting instruction address (r15/pc): 0xdeadc0de
call trace:
     0: lr: 0xdeadc0de
```

### 주소 대역으로 위치를 판단

| 대역 | 무엇 |
|---|---|
| `0x0800xxxx` | 플래시 — 우리가 구운 코드 |
| `0x2000xxxx` | SRAM — 변수, 스택 |
| `0x4000xxxx` | 페리페럴 레지스터 |

**상위 두 자리만 봐도 그 값이 무엇인지 짐작이 됨.**

### PC가 아니라 LR을 본다

- **PC** = `0xdeadc0de` — 존재하지 않는 주소. **우리 코드가 아니므로 단서가 되지 않음**
- **LR** = `0x0800123f` — 플래시 영역. **"어디서 이 호출을 했는가"**

`bl`(branch with link) 명령이 실행될 때 **복귀 주소가 LR에 자동 저장**되기 때문에,
PC가 쓰레기값이어도 LR로 호출자를 역추적할 수 있음.

콜 트레이스는 스택이 깨져 있어 쓸모가 없었음.

---

## 4. 소스 위치 특정

Cortex-M은 Thumb 명령어만 실행하므로 주소의 **비트 0은 "Thumb 상태" 표시**이고 주소의 일부가 아님.
LR을 주소로 쓰려면 그 비트를 마스킹해야 함.

`0x0800123f` → 비트 0 마스킹 → `0x0800123e`

```bash
arm-zephyr-eabi-addr2line -e build/zephyr/zephyr.elf 0x0800123e
→ app/src/main.c:21
```

**19행이 점프한 줄인데 21행이 나온 것이 정상.**
LR은 *복귀 주소*, 즉 호출 **다음** 명령을 가리킴.

> **판독 규칙 : LR로 나온 줄의 바로 위를 본다.**

### `.elf`를 쓰는 이유

빌드 산출물은 두 가지이고 담고 있는 것이 다름.

| 파일 | 내용 | 용도 |
|---|---|---|
| `zephyr.hex` | 기계어만 | 보드에 굽는 것 |
| `zephyr.elf` | 기계어 + **디버그 정보(주소 ↔ 소스 위치 대응표)** | PC에 남겨 두고 분석 |

보드에는 대응표가 올라가지 않음. **보드가 뱉은 숫자를 PC의 대응표로 번역하는 것**이 이 절차임.

## 5. 2차 실험 — Thumb 비트가 fault 종류를 바꾸는가

주소 하나만 바꿔 변인을 분리해 봄.

| 값 | 마지막 자리 | 2진수 | 비트 0 |
|---|---|---|---|
| `0xDEADBEEF` | F | 1111 | **1** (Thumb) |
| `0xDEADC0DE` | E | 1110 | **0** (ARM 상태 요청) |

**가설** : 비트 0이 0이면 Cortex-M에 없는 ARM 상태를 요청하는 것이므로
`UsageFault (INVSTATE)` 가 날 것.

**결과** : 여전히 `MPU FAULT / Instruction Access Violation`.
PC는 `0xdeadc0de` 그대로 (이미 짝수라 마스킹해도 변화 없음).

### 왜 틀렸는가

```
BLX 실행 → PC에 0xDEADC0DE 적재 → 그 주소에서 명령어 인출 시도
                                        ↓
                            MPU가 여기서 먼저 차단 (IACCVIOL)
                                        ↓
                            (T 비트 검사까지 도달하지 못함)
```

**인출이 T 비트 검사보다 먼저임.** 명령어를 가져와야 실행 여부를 따지는데
애초에 가져오지 못했으므로 T 비트는 검사 대상이 되지 않음.

**두 문제가 동시에 있으면 앞 단계의 것만 드러남.**
"주소가 잘못됨"이 "실행 방식이 잘못됨"보다 먼저 걸림.

### 미실시 — 변인 분리 방법

가설이 틀린 것이 아니라 **가려진** 것일 수 있음.
확인하려면 **"주소는 유효한데 T 비트만 0"** 인 경우를 만들면 됨.

```c
uintptr_t addr = (uintptr_t)&main;           /* 실제 존재하는 함수 → MPU 통과 */
((void (*)(void))(addr & ~(uintptr_t)1))();  /* 비트 0만 0으로 */
```

MPU를 통과하므로 T 비트 검사까지 도달할 것으로 예상되나, **아직 실행하지 않았음.**

## 6. 정리

### 확보한 절차

```
크래시 덤프 수신 (UART)
   → 주소 대역으로 각 값의 성격 판단
   → PC가 우리 코드가 아니면 LR 채택
   → Thumb 비트 마스킹
   → addr2line + zephyr.elf
   → 소스 파일:행
   → 그 줄의 바로 위가 원인 지점
```

### 두 번의 예측 실패

| 예측 | 실제 |
|---|---|
| 읽기는 즉시 fault | **통과, 0 반환** |
| 비트 0이 0이면 UsageFault | **MPU FAULT (인출이 먼저 걸림)** |

두 번 다 **모델을 수정하고 이유를 확인**했음.
실험의 값어치는 예측이 맞은 데 있는 것이 아니라, 틀린 이유를 알게 된 데 있음.

### 부수 관찰 — Kconfig 옵션의 비용

`CONFIG_EXTRA_EXCEPTION_INFO=y` 하나를 추가하니 **FLASH 17120 B → 24224 B (+7 KB).**

512 KB 중 7 KB는 여유롭지만 플래시 64 KB인 MCU였다면 11%임.
**MCU에서 "기능을 켜는 것"은 곧 "메모리를 쓰는 것"** 이라는 점이 숫자로 드러남.
